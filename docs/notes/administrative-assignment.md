## Assignment rules

- A supplied source country constrains locality polygons, nearby locality points and administrative fallbacks. Without one, the most specific containing administrative polygon supplies the constraint. Containing localities still precede nearby points, then localadmin and county fallbacks; the distance limit remains 5 km.
- Country compatibility uses the existing sovereign-output conventions and Palestine aliases. A candidate's unambiguous country ancestor also admits a source filed under its sovereign (for example a Finnish address in an Åland locality). This is import compatibility, not a change to the territory's output country. Danish and British territories keep their existing output conventions.
- A locality directly parented by a region is reparented only when its point has exactly one containing region in the same country and that region disagrees. Its inherited region column and affected descendants' search-scope ancestry are updated together with the parent link.
- These rules do not repair malformed polygons, competing region polygons, or contradictory county/localadmin hierarchies by flattening them. Missing or ambiguous spatial evidence leaves the source parent intact. Source defects outside these rules remain unresolved rather than being hidden by place-name overrides. Postal-centroid repair is outside this change: postcode association retains its existing spatial path, including the country corroboration that can reject a misplaced centroid.

The fictional world in `tests/synthetic/world.rs` has a border house whose nearest settlement is foreign, and Falkenstadt with a stored Delta parent inside Epsilon. Both regression checks fail with the base builder. Suggestions, reverse lookup and model-backed forward lookup check the corrected assignment; stated-country contradictions remain rejected or structured fallbacks with `good_match=false`. Resolver conflict guards, postcode compatibility and fallback code are unchanged.
