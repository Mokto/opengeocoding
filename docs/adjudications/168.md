## 2. Ikorodu Road: proven mixed-campus query, unresolved replacement reference

Case `address-km-18-ikorodu-road-orisigun-kosofe-ketu-edo-stat` pairs a Lagos street address with an Edo institution point and region.

- The institution's [official contact page](https://gvu.edu.ng/contact-us), retrieved **2026-10-18**, undated live page, explicitly distinguishes **Ogwa, Edo Campus: KM 1, Ogwa-Ehor Road, Ogwa, Edo State** from **Orishingun, Lagos Campus: Km 18 Ikorodu Road, Orisigun, Kosofe Ketu, Lagos**. It establishes campus-specific address text, not a campus coordinate or postal boundary.
- [Wikidata Q7410732, revision 2534172239](https://www.wikidata.org/w/index.php?title=Q7410732&oldid=2534172239), inspected 2026-10-18, describes the university in Ogwa and supplies Edo State (`P131`), but its unsourced street-address statement (`P6375`) is the Lagos address. Combining these fields produced the hybrid query. The coordinate statement's citation is Google Maps, not an admissible independent gold source. No coordinate was extracted from that citation during this investigation.
- The service returns Ketu in Lagos, while the query explicitly says Edo. That does not prove a correct answer: a stated-state conflict can still expose resolver behavior independently of a defective reference.

The **legacy**, not newly sourced, gold point is **6.516754, 6.196853**, six-decimal WGS84 representation, radius **1 km**, region `NG-ED`, street-level minimum. Its numerical precision is not evidence of accuracy or that it belongs to the queried campus. The university's contact text supplies no positional precision.

### Follow-up: a registry locality point is not a campus point

The [National Universities Commission's private-university register](https://www.nuc.edu.ng/nigerian-univerisities/private-univeristies/), entry **44**, inspected **2026-10-18**, names Glorious Vision University in **Ogwa, Edo State**, established 2011. This is an institutional-registry corroboration of the Edo identity, not a coordinate/boundary record for the Lagos campus. The live register supplies no release identifier or campus geometry; its establishment year is not a data release date.

[ROR record 005nxh826](https://ror.org/005nxh826), [v2 JSON](https://api.ror.org/v2/organizations/005nxh826), record last modified **2026-02-24**, inspected **2026-10-18**, is openly licensed **CC0** and links Wikidata Q7410732. Its location is explicitly `geonames_id=2327517`, **Ogwa**; the coordinates **6.50639, 6.21109** are under `locations[].geonames_details`, with country subdivision `ED`. They are a **locality point**, not a main-campus survey, address point or Lagos-campus point. Five-decimal representation does not imply building precision. They are about **1.95 km** from the legacy point, outside the existing 1 km radius. Substituting this record and widening the radius would change granularity rather than validate the original query, so neither was done.

No inspected openly licensed institution/campus registry supplied a campus-specific point. A map/geocoder listing is not a replacement. The existing corpus also has undecided country-conflict cases, so changing this one to `none`, `any_of` or `unscored` would additionally decide or relax conflict policy, not recover an authoritative geographic reference. The original hybrid query is therefore retained without a newly invented rejection expectation. A valid Ogwa address or a Lagos-campus address can later be added as a separate, independently sourced case; it must not silently replace this case's ID or query.

**Verdict:** a campus conflation in the reference query is proven; an erroneous source coordinate is **not** proven. **Unresolved:** there is no admissible pinned campus-specific point/boundary record here that can replace the legacy expectation. Keep the original case, Edo expectation, radius, components and failure visible, with an unresolved review note. Do not substitute Lagos/the service's point, remove the stated state, label this passing, or silently turn the institution's address into a different case. Completion requires an openly licensed campus-specific registry point and administrative record, plus an explicit decision on the original contradictory query. The older known-failure note is historical triage, not validation of either coordinate.

## 3. Isa Town: stale administrative reference, not an index code defect

Case `city-isa-town-4ab705`, query `Madīnat ‘Īsá, Southern Governorate, Bahrain`.

- [Wikidata Q1017673, revision 2459919356](https://www.wikidata.org/w/index.php?title=Q1017673&oldid=2459919356), modified **2026-02-01**: its only `P131` points to **Q856539, the former Central Governorate**. It has neither an end-time qualifier nor a current Southern Governorate statement. The generator's unqualified `wdt:P131*` traversal therefore yields `BH-16`. Filtering dated statements would not repair this unqualified stale edge.
- Bahrain's [Decree 70/2014](https://www.lloc.gov.bh/Legislation/HTM/D7014), issued/effective **2014-09-23**, abolishes the Central Area Municipality. This is a municipality decree, not by itself proof of a specific point's governorate.
- [Decree 71/2014](https://www.lloc.gov.bh/Legislation/HTM/D7114), issued/effective **2014-09-23**, article 1, names four electoral regions (Capital, Muharraq, Northern, Southern) and explicitly makes their extents those of their governorates. There is no current Central region in that list.
- The Ministry of Municipalities Affairs and Agriculture's [Southern Area Municipality description](https://www.mun.gov.bh/newportal/en/southern-area-municipality/about-municipality), retrieved **2026-10-18**, undated live description, identifies Isa Town at its northern extent and names Isa Town facilities among its landmarks. This corroborates the current named-place assignment, not a high-resolution polygon survey.
- [Southern Governorate, Wikidata Q838532 revision 2529394607](https://www.wikidata.org/w/index.php?title=Q838532&oldid=2529394607), inspected 2026-10-18, supplies the CC0 code **BH-14**. [ISO's Bahrain entry](https://www.iso.org/obp/ui/#iso:code:3166:BH) is the code authority, but the fetched page was a terms/sign-in shell, not a verified code table/history. The often-reported **2015-11-27** ISO deletion date for `BH-16` is not independently pinned here and is not needed to infer it from the service. Do not misdescribe `BH-16` as an old Southern code: it denotes Central, not Southern.

The retained town point is WGS84 **26.173611, 50.547778**, rounded to six decimals from Q1017673's approximately **26°10′25″N, 50°32′52″E**. Its Wikidata precision is unspecified; the existing **6 km** radius is a locality tolerance, not boundary precision. No new point or polygon vertices were copied. `BH-14` is governorate-level precision.

**Verdict:** the current named locality belongs to Southern; the expected Central code comes from stale reference ancestry. Select **Q838532** as the seed's region source while retaining Q1017673 for identity, country and coordinates. This **replaces** the stale code rather than adding another acceptable answer. The seed's review records the supporting citations. This decision does not certify every point within the 6 km tolerance as Southern, or establish the exact boundary at survey precision.
